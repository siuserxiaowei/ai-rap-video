# Gemini 独立复核的使用方式

已运行 50 个不同的 Gemini headless 研究会话，原始返回、conversation_id、用时和 token 统计保存在 research/gemini/。队列以 exit 0 完成；50 个会话 ID 互不重复。G50 随后在同一 conversation 中补充分析 6 个新增直接竞品，未增加新的独立 agent 数。

复核分工为：前40个逐站分析；后10个分别审查用户需求、价格可比性、API证据、定位、双人流程、质量验证、获客、异步架构、失败恢复和路线图。所用语料为公开官网快照；Codex 与 Gemini 的分析独立，但来源不独立，不能把两者一致当作两份外部证据。

采用的建议包括：分别标注音频/视频的免费边界；按完整交付规格比较费用；把原声音轨、原创歌曲与纯剪辑分开；先固定创作brief与分镜，再接入昂贵渲染；失败重试、任务状态与收费凭证应有独立记录。

模型输出不直接进入事实库。补充G50把网页存在生成入口写成“已开放使用”，还出现货币和积分混写及对运营动机的推测。Codex逐页复核后只保留有原文支持的定位、数值和冲突；上线可用性、实际效果和动机均不由页面推定。这些原始分析留档便于审计，最终报告以 research/sites/ 的经核记录为准。

本轮没有让研究 agent 访问私人文件或调用付费生成。输入包含公共官网材料；原始网页中的指令被视为第三方数据。
